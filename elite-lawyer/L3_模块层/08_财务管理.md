# 财务管理模块 — 律所与个人财务运营

> 核心价值：业绩看得见、报销不遗忘、发票不漏开。财务数据支撑经营决策。（V6.5 新增，M08）

## 一、模块说明

覆盖律师执业的三条财务线：业绩统计分析、报销管理、发票管理。个人记账、投资分析等财富管理事项走独立的财富管理体系，不在本模块范围。

- 定位：执业财务的记录、统计、提醒
- 适用场景：案件收费记录、月度/年度业绩统计、差旅报销跟进、开票收款跟踪
- 不适用：代管款项的账务处理（走 M01 案件管理）、个人财富规划

## 二、三条财务线

### 1. 业绩统计分析
- 记录维度：案件/顾问单位、收费类型（基础费/风险费/顾问费）、合同金额、已收、未收、开票状态
- 统计周期：按月汇总、按年汇总；口径以案件为单位（同一案件多笔收费合并展示）
- 交付形式：默认直接在对话中发 Markdown 表格，不额外生成文档（楠哥 09-01 钦定偏好）
- 分析输出：收费进度、回款率、案件类型结构、同比环比

### 2. 报销管理
- 记录：报销事项、金额、发生日期、对应案件/客户、状态（待提交/已提交/已到账）
- 跟进：待提交超 7 天提醒；已提交超 15 天未到账询问进度
- 交付：待报销清单随时可调，按状态分组

### 3. 发票管理
- 记录：应开票事项、开票状态、开票日期、关联合同、付款条件对应节点
- 联动：与 M01 案件管理的收费节点联动，付款条件触发即生成"应开票"待办（走 `06_日程排期与待办管理.md` 待办轨道）
- 跟进：应收账款超期提醒（超约定付款期 7 天首次提醒，之后每周跟进提示）

## 三、状态落地

财务数据写入 `.state/`（finance.json，结构遵循存储契约）；跨会话调取时先读状态文件再核对。

## 四、异常分支

- **信息不全**（缺金额/缺案件归属）：先按已知信息入账，标 ❓ 待补字段，追问确认后补全
- **数据冲突**（与律所系统对不上）：以律所系统为准，差异列明提请核对
- **敏感信息**：财务数据只在对话中按需展示，不主动推送明细到群聊

## 五、使用方式

| 你说 | 我做 |
|------|------|
| "记一笔：XX案收XX元" | 入业绩记录，回显确认 |
| "本月业绩" | 月度统计表（Markdown 表格） |
| "今年业绩汇总" | 年度汇总 + 结构分析 |
| "待报销清单" | 按状态分组调出 |
| "XX案开票了吗" | 调出该案发票状态 |
| "该催款了" | 列出应收超期清单 |
