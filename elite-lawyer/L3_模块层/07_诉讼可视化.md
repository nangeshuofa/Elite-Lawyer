# 诉讼可视化模块 — 诉讼图表重绘与出图

> 核心价值：把凌乱或"AI 味"的诉讼图重画成克制、专业、可直接进卷宗的图，交出可继续编辑的源文件。A4 物理尺寸确定性排版，同输入必出同图。

## 一、模块说明（定位 + 适用场景）

**定位**：把案情、程序、关系转化为法院可用的可视化图表。本模块定义触发与质量口径，绘制执行调用底层引擎完成。

**底层引擎**：同环境已装技能 `mqc-litigation-visual-redraw`（诉讼图重绘引擎）。本模块触发后按其规范执行语义映射与重绘；引擎不可用时按异常分支降级。

**适用场景**：
- 起诉状 / 代理词随附事实经过时间轴
- 庭审出示攻防路径图、请求权基础图
- 向客户呈现当事人关系 / 担保关系 / 股权资金控制关系
- 复杂案件向合议庭汇报的程序图

### 三类图

| 类型 | 典型图 |
|------|--------|
| 时间轴 | 事实经过时间轴、诉讼时效 / 保证期间图、甘特式期间图 |
| 流程图 | 案件程序 / 诉讼流程图、请求权基础图、攻防路径图 |
| 关系图 | 当事人关系图、担保法律关系图、股权·资金·控制关系图 |

### 输出与风格

- 默认输出 **SVG + PPTX**（可继续编辑源文件）；可选 PNG、VSDX、drawio
- 三种风格：**奇川风 / 歸藏风 / 白描**（白描黑白最适合法院卷宗）
- 七种版式按内容自动匹配；不指定风格时默认白描

### 硬约束（红线）

1. **图上文字只许删减不许改写**——法律含义零改动，改一个词都会在出图前被拦下（对接 L2-05 交叉式验证的图文比对）
2. 不画柱状图、饼图与地图；不做纯文字排版
3. **不出法律意见**——图是呈现工具，法律判断仍由对应工作流产出并经律师审核
4. 零外部依赖（无需 graphviz）、不联网、不上传案件信息

## 二、交互式工作流

```
触发：用户给图（手绘/截图/Mermaid 导出/PPT 截图）或直接给一段案情文字
  ↓
Step 1 — 意图确认：图类型（时间轴/流程图/关系图）+ 用途（卷宗/庭审/客户）+ 风格（默认白描）
  ↓
Step 2 — 内容提取：从原图或案情文字提取节点与连线；
  原图文字只提取不改写；引用案件档案时以 .state/ 与案卷文字为准
  ↓
Step 3 — 调用引擎重绘（mqc-litigation-visual-redraw）：
  语义映射 → 版式匹配 → A4 排版计算 → 输出 SVG + PPTX
  ↓
Step 4 — 硬约束自检（对接 L2-05）：
  - 交互式校验：出图清单（版式/风格/删除的文字）回律师确认后交付
  - 图文比对：逐节点核对图上文字与源文字，只删不改
  ↓
Step 5 — 交付：源文件 + 打印/归档建议；关联案件的出图文件随案件工作区归档
```

### 异常分支

| 异常场景 | AI 行为 |
|----------|---------|
| 信息不全（节点/时间/主体缺失） | 一次性列出缺失项（最多追问 2 轮）；仍不全则交付"框架版"并标注 ⚠️ 缺失项 |
| 引擎不可用 | 降级为结构化文字版（时间轴表格/关系清单），在输出开头标注局限性声明，注明引擎恢复后可重绘 |
| 原图文字与案卷冲突 | 以案卷文字为准，冲突点列出请律师裁决（对接 L2-05 重大冲突阻断），不得静默取其一 |
| 出图内容涉密 | 按红线执行：不上传、不外发，仅本地生成与本地归档 |

## 三、引用 L2 规则

- **质量标准**：引用 L2-04 质量控制机制——图内文字准确性按文书级要求执行
- **校验**：引用 L2-05 核准校验机制——交互式校验（出图前确认）+ 交叉式验证（图文比对）
- **优先级**：引用 L1-02 全局优先级，出图任务按事项本身优先级排序
- 本模块不重复定义上述规则（Single Source of Truth）

## 四、使用方式

| 你说 | 我做 |
|------|------|
| "把这张图美化一下 / 重画成能交法院的" | 进入重绘工作流，默认白描风格 |
| "把这段事实画成时间轴" | 无原图直出，从案情文字提取节点 |
| "画 XX 案当事人关系图" | 调取案件档案生成关系图 |
| "出庭审用的攻防路径图" | 结合诉讼策略输出攻防图 |
| "改成黑白 / 换成奇川风" | 同内容换风格重出，文字不动 |
| "这张图文字太多了" | 只删不改地精简文字后重排 |
