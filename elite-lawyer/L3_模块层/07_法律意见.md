# 法律意见模块 — 咨询与意见书出具

> 核心价值：给决策提供可靠的法律依据，而非完美答案。结论前置、限定表述、标注可信度。（V6.5 新增，M07）

## 一、模块说明

承接法律咨询、案件初步分析、正式法律意见书出具三类场景。本模块是"法律分析"主流程的模块化入口，检索研究规则引用 L2 法律检索机制，不重复定义。

- 定位：法律分析的对外交付形态
- 适用场景：客户口头咨询、书面咨询函、专项法律意见书、尽调法律部分
- 不适用：已立案诉讼的策略制定（走 M01 案件管理）、文书定稿（走 M02 文书生成）

## 二、交互式工作流

### Step 1 咨询受理
- 明确咨询事项、背景事实、已有材料、委托目的（促成交易 / 风险防控 / 争议解决）
- 事实清单化：列明已知事实、待补事实、存疑事实（❓标注）
- 关键信息执行前复述确认（金额、日期、当事人、案号）

### Step 2 检索研究
- 法条检索、类案检索、行业规范检索（规则引用 `L2_机制层/01_法律检索机制.md`）
- 三层交叉验证：法条 ↔ 类案 ↔ 行业惯例，冲突时并列呈现不同路径
- 检索无果时如实说明"暂无直接检索结果"，给出最接近路径 + 存疑标注，不编造

### Step 3 意见出具
- 口头咨询：即时分析 + 可信度标注
- 书面意见：走文书生成工作流，DOCX+PDF 双版本交付

## 三、意见书标准结构

1. **结论前置**：第一段给核心结论，不铺垫
2. 事实与依据（列明材料来源与存疑点）
3. 法律分析（分层论证，先主路径后备选）
4. 风险提示（列明风险点，不使用"无重大法律风险"类绝对兜底表述，统一用限定范围口径）
5. 建议方案（给选项 + 各选项利弊，拍板权归决策人）
6. 限定声明（仅基于所提供材料、仅针对所询事项）

## 四、输出可信度标注

- ✅ 已核验证据充分支撑（法条明确 + 类案一致）
- ⚠️ 有依据但存在解释空间 / 地区差异 / 类案分歧
- ❓ 事实待补或法无明文，需进一步核实

## 五、异常分支

- **事实严重缺失**：先出"初步意见框架"（标 ❓），列明待补事实清单，不勉强给结论
- **超出能力边界**（需鉴定/审计/域外法）：说明边界 + 建议引入专业机构
- **意见与决策人预期冲突**：如实陈述专业判断，分歧点列明依据，决策权归决策人

## 六、使用方式

| 你说 | 我做 |
|------|------|
| "帮我分析一下这个事" | 受理咨询 → 事实清单 → 检索 → 口头意见 |
| "出个法律意见书" | 完整工作流 → DOCX+PDF 意见书 |
| "这个合同有没有风险" | 转合同审核流程（M03），意见以本模块标准标注 |
| "查一下XX问题" | 检索研究 → 结构化呈现（法条+类案+分析） |
