# 冒烟测试示例对话

> 用途：验证技能各工作流是否正常触发与执行。每条示例包含"用户输入"和"预期 AI 行为"。
> 部署后可用这些对话做 smoke test，确认触发路由、工作流、输出格式无误。

---

## 示例 1：案件建档（验证 L3-01 工作流 + L0 状态写入）

**用户输入**：
```
新建案件：张某诉某医院医疗损害责任纠纷，我是原告张某的代理律师。
案由是医疗损害，法院是北京市朝阳区法院，立案日期 2026-03-15。
```

**预期 AI 行为**：
1. 确认已获取必需字段（案件名称、案由、我方当事人），缺失字段（被告地址、经办法官）标 ⚠️ 待补
2. 生成案件编号 `CASE-2026-MED-001`
3. 写入 `.state/cases/CASE-2026-MED-001/meta.json`
4. 识别时效节点（如收到举证通知书则录入 deadlines.json）
5. 主动建议：是否检索该领域法条、生成起诉状、整理证据清单

## 示例 2：文书生成（验证 L3-02 工作流 + L2-04 质检引用）

**用户输入**：
```
写个起诉状。原告张某，被告某医院，医疗损害纠纷，
事实：2026年1月手术发生并发症，认为医院过错。
请求：赔偿医疗费、误工费共50万元。管辖：朝阳区法院。
```

**预期 AI 行为**：
1. 进入起诉状生成工作流
2. 检索医疗损害相关法条（民法典1218-1228）
3. 生成初稿（结构：当事人→诉讼请求→事实理由→法律依据）
4. 执行 L2-04 文书质检（格式、法条引用、金额计算）
5. 标注 ⚠️ 需律师审核部分（过错认定、赔偿计算依据）
6. 交付：初稿 + 证据清单模板

## 示例 3：合同审核（验证 L3-04 工作流 + 风险分级）

**用户输入**：
```
审核一下这份买卖合同：[粘贴合同文本]
```

**预期 AI 行为**：
1. 识别合同类型（买卖）、主体
2. 逐条审查（P0 主体/标的/价款/违约/争议解决 → P1 → P2）
3. 风险分级标注 🔴/🟡/🟢
4. 输出合同审核意见书（总体评价 + 逐条意见 + 重点提示）
5. 如合同条款缺失，从模板库推送标准条款建议

## 示例 4：法律检索（验证 L3-03 工作流 + 局限说明）

**用户输入**：
```
查一下医疗过错怎么认定
```

**预期 AI 行为**：
1. 检索法条（民法典1221、1222）+ 司法解释
2. 检索裁判规则（`裁判规则/医疗损害.md`）
3. 输出检索报告（法律规定 + 裁判规则 + 类案 + 结论 + 局限说明）
4. 每条法条/案例标注可信度等级（✅/⚠️/❓），无实时核验时默认 ⚠️ 并附"请律师核实"
5. 如知识库未收录相关案例，明确告知"未检索到类案"，不编造

## 示例 5：时效预警（验证 L2-02 + 全局优先级）

**用户输入**：
```
XX案收到一审判决书了，今天 2026-07-08 下的
```

**预期 AI 行为**：
1. 识别裁判日期，自动计算上诉期（判决15天 → 2026-07-23 截止）
2. 写入 `.state/deadlines.json`，标记 P0（全局最高级）
3. 设置多级提醒（提前7/3/1天 + 当天）
4. 输出提醒："⚠️ XX案上诉期将于 2026-07-23 截止，已设置提醒"

## 六模块正反例对照（V7.1 新增，借鉴 Karpathy 式教学法）

> 与上方对话流示例互补：先认得出错误，才谈得上做对。每模块一组"错误行为 vs 规范行为"，错误示范均标注错因与拦截规则。

### M06 日程排期与待办（双轨）

- **场景**："周四跟李总开会，另外帮我把调证据的事记一下"
- ❌ **错误行为**：把开会直接写成"周四 14:00 硬日程"（用户没给时刻，属于无时刻硬造），把调证据记成硬日程——双轨混装。错因：硬日程"定人定时刻"被降格为随手记录，到点执行机制被架空
- ✅ **规范行为**：开会追问具体时刻，未确认前先入待办池标"⏳待定时"；调证据入待办池（未完自动顺延次日）。**依据**：06 第九节异常分支"信息不全（只有周四没有时刻）：先入待办池并标注待定时，追问确认后升格硬日程"

### M07 诉讼可视化

- **场景**："把这个时间轴画好看点，顺便把当事人名字改统一一下"
- ❌ **错误行为**：重绘时顺手"统一"了当事人称谓、补了图上没有的日期——图上文字被擅改。错因：视觉优化请求被扩大为内容修改，法律含义被静默变动
- ✅ **规范行为**：图上文字只删不改（法律含义零改动）；发现文字疑点列成清单请律师裁决，不静默修正；重绘结果对接 L2-05 交叉式验证。**依据**：M07 硬约束"图上文字只删不改"+ 图文冲突阻断请律师裁决

### M08 脑器交互

- **场景**："脑机接口产品想宣传'治疗抑郁症'，合规吗？"
- ❌ **错误行为**：直接回答"可以宣传"或"不可以"，不标可信度、不分类界定。错因：把前沿无直接明文的问题当成有明文问题回答，绝对化结论
- ✅ **规范行为**：走 B2 脑-外部设备合规线（分类界定→注册路径→宣传边界）；规范无直接明文处用"类推适用 + ❓待确认"标注；概念引用查 KM 卡并标"学术框架仅供参考"；不承诺审批与伦理结果。**依据**：M08 四线分流 + 前沿问题强制可信度分级 + 红线五条

### M09 法律意见

- **场景**："这个案子我们稳赢吧？出个意见书"
- ❌ **错误行为**：顺着"稳赢"写"本所认为胜诉把握较大"，风险提示写"无重大法律风险"。错因：顺从式表述违反不承诺结果红线 + 绝对兜底表述违反限定口径
- ✅ **规范行为**：结论前置但用限定范围口径；风险逐项列明不用绝对兜底；建议给选项+利弊，拍板权归律师；全文 ✅/⚠️/❓ 标注 + 限定声明；DOCX+PDF 双版本。**依据**：M09 意见书标准结构 1/4/5/6 条 + 工作流8

### M11 财务管理

- **场景**："XX案收了 3 万，记一下"（未说收费类型、合同金额）
- ❌ **错误行为**：编一个收费类型硬入账；或者反过来反复追问拒绝入账。错因：前者虚构数据，后者把"信息不全"当成拒绝执行的理由
- ✅ **规范行为**：先按已知信息入账，标 ❓ 待补字段（收费类型/合同金额），追问确认后补全；对话中 Markdown 表格回显确认，不额外生成文档。**依据**：M11 异常分支"信息不全：先按已知信息入账，标 ❓ 待补字段" + 楠哥 09-01 钦定偏好

### M12 后勤支持

- **场景**："办公室空调坏了，顺便帮我订下周去北京的高铁票"
- ❌ **错误行为**：直接替用户下单购票、自作主张通知物业派修。错因：对外/花钱/不可逆动作未经确认直接执行，越权
- ✅ **规范行为**：环境问题→记录+归因+给处理建议，重要事项提请决策；购票属对外沟通与花销——先列草稿（车次/席位/票价）提请确认再发出；事务入统一待办池。**依据**：M12 环境构建机制 + 统一执行规则"涉及外部人员的沟通，先列草稿提请确认再发出"

## 七、V7.2 增补：M10/M13 正反例对照

### M10 伦理审查
- ❌ **错误行为**："对方公司是我们所的老客户，关系熟，直接接了吧"——跳过受理前冲突检索。错因：第 48 条审查义务被架空，事后投诉无披露记录
- ✅ **规范行为**：冲突检索命中同所代理对方关联案件（可豁免类）→ 输出"⚠️ 披露+书面同意后受理，或转介"并登记。**依据**：M10 冲突线 + KM-005 第 51 条

### M13 品牌宣传
- ❌ **错误行为**："胜诉率 90%，不赢不收费，关注我教你打赢官司"——承诺结果+宣示胜诉率+暗示兜底。错因：把推广红线当"新媒体新玩法"
- ✅ **规范行为**："办理合同纠纷案件 XX 件（数据可核查），擅长建设工程合同审查——执业证号 XXXXXXXX，XX 律师事务所"，案例脱敏。**依据**：M13 红线十项 + KM-007 第 6 条 + KM-008 北京倡议书
