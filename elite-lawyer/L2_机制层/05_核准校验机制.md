# 核准校验机制 — 五层数据与决策校验体系

> **版本**：V1.0 | **最后更新**：2026-09-20（黄律师审定）
> **定位**：关键数据录入、重要决策输出前的多道校验闸门，与 L2-04 质量控制机制（文本层面校验）互补——04 管输出质量，05 管数据与决策的入库前把关。
> **总原则**：系统输出 → 校验 → 确认无误后入库；未过校验的数据一律不落盘。

## 一、交互式校验（Interactive Verification）

**定位**：关键数据录入、重要决策输出时的人工确认。

**触发时机**：
- 关键数据录入
- 重要决策输出
- 系统升级后

**执行方式**：系统输出 → 用户确认 → 确认无误后入库

**典型场景**：待办新增 / 客户信息录入 / 健康数据记录 / 系统模块变更

**校验语句**：`楠哥，请确认以下内容是否准确：[内容]。回复"确认"或指出错误。`

**响应处理**：
| 用户响应 | 系统动作 |
|---------|---------|
| 确认 | 入库 |
| 指出错误 | 触发回滚锁，修正后重新校验 |
| 无响应 | 暂存待确认区，不自动入库 |

## 二、交叉式验证（Cross-Verification）

**定位**：同一信息在多个模块中自动比对，发现不一致立即提示。

**触发时机**：同一信息出现在多个模块时 / 系统定期扫描时

**执行方式**：自动比对不同模块中的同一数据，发现不一致立即提示。

**典型场景**：
- 场景角色名 vs 黑名单
- 周日程 vs 动态日程
- 金句库 vs 知识卡片
- 客户列表 vs 案件记录
- 称呼规则 vs 场景配置

**校验示例**：`检测到冲突：场景3角色为"小玲"，黑名单也为"周小玲"，已确认为同一人。`

**比对维度**：姓名一致性 / 时间一致性 / 数值一致性 / 分类一致性 / 状态一致性

**冲突处理**：
| 级别 | 处理 |
|-----|------|
| 轻微冲突 | 提示但不阻断 |
| 重大冲突 | 阻断输出，请求人工裁决 |

## 三、第三方基准核对（Third-Party Baseline Check）

**定位**：与外部权威来源比对，标注差异。

**触发时机**：外部数据引用 / 法规检索 / 客户信息核对 / 财政统计数据查询

**执行方式**：与外部权威来源比对，标注差异。

**典型场景**：统一社会信用代码 / 法条引用 / 财政数据查询 / 行业标准

**校验示例**：`四医院统一社会信用代码 125101004507520821，与公开信息一致 ✅`

**核对来源**：
- 国家企业信用信息公示系统
- 中国裁判文书网
- 法律法规数据库
- 政府公开数据

**差异处理**：
| 结果 | 标记 |
|-----|------|
| 一致 | 已验证 |
| 不一致 | 标注差异，提示可能原因 |
| 无法核对 | 待验证 |

## 四、巡查测试（Patrol Testing）

**定位**：全系统定期自动扫描，检查数据完整性、规则冲突、待更新项。

**触发时机**：
- 每周日 20:00（周报生成时）
- 每月最后一个周日（知识发现引擎扫描时）

**执行方式**：自动扫描全系统。

**输出内容**：完整性报告 / 异常清单 / 建议动作

**校验示例**：`检测到健康数据停留在6/24，已超90天未更新，建议补充。`

**扫描维度**：数据完整性（缺失）/ 规则冲突（矛盾）/ 待更新项（过期）/ 待确认项（未处理）/ 模块健康度（异常）

**异常分级**：
| 级别 | 处理 |
|-----|------|
| 🔴 高 | 立即处理，阻断相关功能 |
| 🟡 中 | 本周内处理，不阻断 |
| 🟢 低 | 记录在案，择机处理 |

## 五、人工介入查询测试（Manual Intervention Query Test）

**定位**：用户主动发起抽查，系统实时响应并展示原始记录。

**触发时机**：用户主动发起 / 系统检测到重大异常时

**执行方式**：用户逐层抽查系统数据，系统实时响应并展示原始记录。

**典型场景**：审计数据来源 / 验证规则执行 / 排查异常

**校验示例**：`请查询：2026-05-26 的金句"架构对无序"是否已归入D类？→ 已确认归入D_成长与系统。`

**查询指令**：
- `查询：[关键词]`
- `验证：[数据项]`
- `追溯：[事件]的完整记录`
- `审计：[模块]的所有变更`

**响应格式**：
| 指令类型 | 响应内容 |
|---------|---------|
| 查询结果 | 展示数据 |
| 来源追溯 | 展示原始记录路径 |
| 变更历史 | 展示修改时间线 |
| 关联信息 | 展示相关模块 |

## 运行流程

```
1. 数据录入/输出
2. 交互式校验 ← 用户确认
3. 交叉式验证 ← 多模块比对
4. 第三方基准核对 ← 外部来源
5. 巡查测试 ← 每周日自动扫描
6. 人工介入查询测试 ← 用户抽查
7. 数据入库 / 异常告警
```
