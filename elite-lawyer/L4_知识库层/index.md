## 二、检索协议（AI 读取知识）

```
Step 1 — 读 index.md，根据领域+类型定位分片文件
Step 2 — 用 Grep 工具在目标文件检索关键词（案由/法条号/争议点）
Step 3 — 命中卡片 → 返回卡片全文 + 标注来源文件 + 溯源字段（案号/文书出处，未核标注⚠️）
Step 4 — 关系织网：在 relations.md 中 grep 该卡指纹 → 存在 applies/cites/conflicts
         等关系的，一并返回关联卡，输出更完整的依据链
Step 5 — 无命中 → 明确告知"知识库未收录"，附检索范围，不编造
```

> 溯源纪律（V6.2）：引用知识卡输出意见时，必须带上卡片"溯源"字段（案号+文书来源）；
> 溯源为"待核"的内容不得作为独立结论引用，只能作为线索提示进一步核实。

## 三、写入协议（AI 沉淀知识）

```
Step 1 — 判断知识类型（RULE/TPL/CASE/STRAT/KNOW）
Step 2 — 定位目标分片文件（按领域+类型）
Step 3 — 用 Edit 工具在文件末尾追加标准格式卡片（指纹必填，溯源尽力填）
Step 3.5 — 关系织网（V6.2.1）：单卡沉淀当场与同领域存量卡比较——
          确认关系 → 直接登记 relations.md（AI核验标注）；
          无法确认 → 记入待核队列，不凭印象连线；
          批量导入（一次≥5卡）才走 relations.md 待比较队列
Step 4 — 同步更新本 index.md（如新增了领域标签）
Step 5 — 标注写入时间 + 来源
```

> 指纹规则（V6.2）：案例类卡片指纹=案号（如"指导案例24号"），规则类=领域-主条文号（如"医疗损害-1218"，同号加序号消歧），无法提取条文的用"领域-类型-序号"。
> 存量 21 卡已于 V6.2.1 回填指纹；模板类（TPL）卡片可省略指纹。
> 写入前按指纹 grep 查重，同一案号/文号已存在则合并更新而非新增。

## 四、知识卡片标准格式

**KM 格式（2026-09-19 律师审定为标准格式，样本 KM-001）**：七段式结构——
`卡片编号（KM-XXX）｜卡片标题｜创建日期｜标签` 头部 → 一、核心结论 → 二、法理基础 → 三、常见反驳/适用角度 → 四、法律依据 → 五、话术/操作模板 → 六、实务建议 → 七、关联卡片 → 溯源与织网。
协议字段（V6.2）融入头部：**指纹**（案号/文号，查重与织网锚点）、**可信度**（✅/⚠️/❓）；"溯源与织网"节承载 V6.2 溯源纪律与关系记录。后续新卡片按此格式追加，KM 编号递增。

历史标准格式（v6.2 前卡片沿用）：

```markdown
### [类型] 知识标题
- **指纹**：案号/文号/领域-类型-日期-序号（唯一标识，查重与关系织网的锚点，V6.2 必填）
- **来源**：案件名/任务名/日期
- **领域**：医疗/劳动/合同/...
- **摘要**：一句话核心结论
- **详情**：具体内容（3-5句，可引原文）
- **法律依据**：相关法条/司法解释
- **溯源**：文书来源+页码/条文号（判决书原文、公报、公开检索路径；未核对标⚠️待核，V6.2）
- **可信度**：✅ 官方/办案来源 / ⚠️ 公开报道教学样本 / ❓ 待核
- **复用场景**：何时可再次使用
- **关联**：见 relations.md 中该指纹的关系条目（V6.2 起关系统一登记关系层）
- **添加日期**：YYYY-MM-DD
```

## 六、维护规则

1. **索引先行**：新增知识前先确认 index.md 是否已覆盖该领域，未覆盖则新增分片文件并登记
2. **指纹查重**：写入前按卡片"指纹"（案号/文号）grep 查重，同一指纹合并更新而非新增（V6.2）
3. **来源可查**：每条知识必须标注来源和日期；引用输出时带溯源字段，未核内容不作独立结论（V6.2）
4. **关系织网**：新卡按写入协议 Step 3.5 比较后登记 relations.md；冲突关系必登记；无法确认入待核队列，不凭印象连线（V6.2）
5. **定期健康**：每季度检查失效法条标记、重复合并、待核队列清零（见 L2-03 知识发现机制）
